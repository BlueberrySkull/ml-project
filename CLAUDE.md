# CLAUDE.md

## Задание (исходные требования курса)

Задача проекта - развернуть в облаке модель машинного обучения и обеспечить доступ к ней по сети через Web или API.

Проекты выполняются в командах из 2-3 человека.

Требования к реализации проекта:

- В проекте должна использоваться предварительно обученная модель. Например с huggingface.co или www.kaggle.com. Обучать собственную модель не нужно.
- Исходный код приложения необходимо загрузить на GitHub.
- Рекомендуемая библиотека для реализации Web – Streamlit, для реализации API – FastAPI.
- Приложение должно содержать тесты.
- На GitHub должна быть настроена система Continuous Integration таким образом, чтобы при выполнении push в репозиторий GitHub выполнялся автоматический запуск тестов.
- (Задание повышенной сложности) Необходимо настроить автоматическое развертывание приложения в облачную платформу при выполнении push в репозиторий GitHub, при условии успешного выполнения тестов.

## Команда

Выполняется одним человеком (задание допускает команду 2–3 человек, но не требует её). Поэтому в PLAN.md нет разделения по ролям, а порядок этапов подобран так, чтобы после каждого этапа была рабочая версия приложения.

## Предметная область: ГБУ БДД

Проект реализуется в рамках ГБУ БДД. Исходное обсуждение идеи: <https://chat.deepseek.com/share/9m3qj9mwqo19anup1t>

Во внутренней информационной системе (ИС) ГБУ БДД работают с кадровыми процессами:

- начальники отделов отправляют в отдел кадров табели учёта рабочего времени на согласование, заявки на отпуск, данные по рабочим сменам и сведения о работниках-налогоплательщиках;
- отдел обучения направляет сотрудников на обучение, загружает в систему сертификаты и доверенности.

Система новая, пользователям постоянно приходится объяснять, как ей пользоваться. Отсюда выбранная идея (см. PLAN.md).

## Идея проекта

**«Помощник по ИС»**: RAG-чат-бот, который отвечает на вопросы сотрудников по работе с ИС («как отправить табель на согласование?», «куда загрузить сертификат?»). Ответы строятся **только по базе инструкций** (регламенты, руководство пользователя, FAQ), и в каждом ответе указывается, из какого раздела инструкции он взят.

Пайплайн: вопрос → эмбеддинг → векторный поиск ближайших фрагментов → LLM формирует ответ по найденному контексту → ответ + источники.

**Данные (база знаний):** несколько текстовых файлов с инструкциями/FAQ по ИС (`knowledge_base/*.txt`). Реальные табели, ФИО, ИНН и т.п. в них не используются — только обезличенные примеры (152-ФЗ).

## Масштаб проекта

Задание рассчитано на компактное приложение — ориентир взят из эталонных примеров курса:

- <https://github.com/urfu-online-courses/streamlit_demo_app>
- <https://github.com/urfu-online-courses/ml_fastapi>
- <https://github.com/hamitovrm/orbitr>

В каждом из них: один файл с логикой (модель грузится прямо в скрипте), плоский `requirements.txt`, один `Dockerfile`, один workflow-файл (`test` → `build_and_push`, второй job с `needs: test`), 2–3 простых теста без моков. Web и API в этих примерах — это два разных, самостоятельных приложения, а не один сервис с обоими интерфейсами: в задании сказано «через Web **или** API», то есть достаточно одного.

Соответственно, в этом проекте:

- делаем **только Streamlit-приложение** (Web), отдельный FastAPI-слой не нужен;
- никакого пакета `app/` с подмодулями `rag/llm/api` — код разбит всего на 2 файла (`app.py` и `rag_core.py`, см. структуру ниже);
- без SQLite-логирования фидбека, без отдельного скрипта метрик (Hit@k/MRR — по желанию, для качества самого проекта, но не как отдельная фича);
- если останется время: тонкий `api.py` на FastAPI по образцу `ml_fastapi/main.py` как бонус, не обязателен.

## Модели (предобученные, без дообучения)

| Роль | Модель | Примечание |
| --- | --- | --- |
| Генерация ответа | `bond005/Meno-Tiny-0.1-GGUF` (Qwen2.5-1.5B, дообучена под русский RAG/QA) | запуск на CPU через `llama-cpp-python`; в репозитории на HF есть только fp16-файл (~2.9 ГБ), уже скачан в `models/llm/` |
| Эмбеддинги для поиска | `cointegrated/rubert-tiny2` | через `sentence-transformers`, уже скачан в `models/embedder/` (227.8 МБ) |

`rubert-entity-embedder` (был скачан вручную раньше) для поиска **не подходит**: он строит токенные эмбеддинги для NER, а не эмбеддинги предложений/абзацев, и в проекте не используется.

Веса моделей **не коммитятся** в git. Скачиваются скриптом `scripts/download_models.py` в `models/` (эта папка в `.gitignore`).

## Стек

- Python 3.11+
- Streamlit: чат-интерфейс, единственный способ доступа к модели (Web)
- llama-cpp-python (генерация), sentence-transformers (эмбеддинги), numpy (косинусный поиск top-k — без FAISS, документов немного)
- pytest, ruff
- Docker, GitHub Actions (CI + CD)
- Хостинг: Docker Hub + запуск контейнера в облаке (по образцу эталонных репозиториев) либо Hugging Face Spaces (Docker Space, бесплатный CPU, 16 ГБ RAM) — решим на этапе деплоя. Streamlit Community Cloud не подходит: там около 1 ГБ RAM, а fp16-модель весит 2.9 ГБ.

## Структура репозитория (целевая)

```text
app.py                      # Streamlit UI: чат, вызывает функции из rag_core.py
rag_core.py                 # чистая логика без Streamlit: чтение knowledge_base,
                             # нарезка текста на фрагменты, эмбеддинги, поиск top-k,
                             # сборка промпта, вызов LLM
knowledge_base/*.txt        # база знаний: обезличенные инструкции и FAQ по ИС
scripts/download_models.py  # скачивание моделей в models/ (уже готов)
test_rag_core.py            # тесты на rag_core.py с фейковыми эмбеддером/LLM (без скачивания моделей)
requirements.txt
requirements-dev.txt
Dockerfile
.github/workflows/ci-cd.yml # test -> build_and_push (needs: test)
README.md
```

## Правила разработки

- **Никаких персональных данных.** В репозиторий и облако попадают только инструкции и выдуманные примеры (152-ФЗ).
- Тесты не должны скачивать модели: `rag_core.py` принимает эмбеддер и LLM как параметры (простая инъекция функций), в `test_rag_core.py` подставляются лёгкие фейки.
- Бот отвечает только по найденному контексту. Если релевантных фрагментов нет (score ниже порога), он честно говорит «в инструкциях этого нет, обратитесь в техническую поддержку».
